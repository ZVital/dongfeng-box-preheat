# Автопрогрев Dongfeng Box

Приложение для мультимедийной головы Dongfeng Box (Box / Nammi, Android 8.1):
самостоятельно будит голову по расписанию штатным будильником Android и включает
климат на заданное время, а затем **возвращает настройки в исходное состояние**.

Управление климатом здесь **не эмулируется и не перехватывается** — приложение
просто вызывает тот же публичный AIDL-интерфейс, который использует штатный
интерфейс машины. Никаких прав, root, нативного кода и вмешательства в CAN.

> [!IMPORTANT]
> Проект хоббийный и не проверен производителем. Подробности рисков — в
> [`DISCLAIMER.md`](DISCLAIMER.md). Обязательно прочитайте его перед
> использованием.

| Включение/выключение климата | ✅ проверено, состояние меняется, владелец подтвердил |
| Отправка кадра в шину | ✅ пойман первый исходящий кадр за весь проект |

| Прогрев салона | ❌ штатной интерфейс его не исполняет на этой платформе |

Подробности и доказательства — [`docs/FINDINGS.md`](docs/FINDINGS.md).

## Сборка

Собирается **без Gradle**, напрямую Android SDK и NDK:

```bash
cd app
./build.sh
```

Нужны: `ANDROID_HOME` с `build-tools/35.0.1`, `platforms/android-33`,
и NDK не требуется — в приложении нет нативного кода. Java — JDK из Android
Studio (используется JBR), но подойдёт любой JDK 8+.

На выходе `app/Preheat.apk`, подписан отладочным ключом, который создаётся
при первом запуске сборки.

## Установка

```bash
adb install -r app/Preheat.apk
adb shell am start -n com.qingfan.preheat/.MainActivity
```

Приложение не запрашивает ни одного разрешения.

## Как пользоваться

1. Задать время начала и окончания.
2. Выбрать повтор: один раз, каждый день или конкретные дни недели.
3. Задать мёртвую зону салона: ниже «от» — включаем прогрев, выше «до» — прекращаем.
4. Задать целевую температуру.
5. **ОКЕЙ** — сохраняет расписание и ставит будильники.

Кнопка **ПРОВЕРИТЬ СЕЙЧАС** выполняет те же действия немедленно, без
ожидания будильника.

## Диагностика

В приложении нет экранного журнала: текст нечитаем на расстоянии вождения и
никто его не стал бы чистить. Всё пишется только в системный лог:

```bash
adb logcat -s Preheat
```

Ключевые строки:

| Строка | Значение |
|---|---|
| `ALARM FIRED action=…` | будильник сработал — главная проверка |
| `snapshot: ac=… defrost=… setpoint=…` | состояние снято до прогрева |
| `tick: cabin …C` | очередная проверка раз в минуту |
| `tick: cabin …C outside plausible range, rejected` | чтение температуры подозрительно |
| `restore: setpoint … -> …` | уставка возвращена |
| `loop started` / `loop finished` | цикл контроля запущен / остановлен |

## Как это устроено

```
app/src/com/qingfan/preheat/
├── MainActivity.java      экран расписания
├── ScheduleStore.java     хранение расписания
├── PreheatReceiver.java   приём будильников, запуск и остановка прогрева
├── PreheatLoop.java       поминутный контроль температуры, пока прогрев активен
├── Snapshot.java          состояние до прогрева и его восстановление
├── BootReceiver.java      перевзвод будильников после перезагрузки
└── CanClient.java         AIDL-вызовы CAN-сервиса
```

Будильник нужен только чтобы **разбудить систему**. Дальше голова уже не спит, и
контроль идёт обычным программным таймером внутри процесса — раз в минуту.
Запасной вариант на случай, если процесс всё-таки уснёт, — это будильник
окончания: он выключит климат в любом случае, просто позже.

## Экранирование

Цели рассчитаны на штатную геометрию: 1920×1080 при density 160, поэтому
`1dp = 1px` и вёрстка идёт в пикселях. Размеры текста заданы в абсолютных
единицах, а не в `sp`: на машине увеличен системный масштаб шрифта, и `sp`
давал бы текст примерно втрое крупнее заданного.

Палитра снята с самой панели: основной фиолетовый `#AE83E3`, яркий `#B963FD`,
тёплый `#835224` (взят из ресурсов штатного лаунчера), фон `#F6F5F7`.
